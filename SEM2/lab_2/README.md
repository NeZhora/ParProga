# Лабораторная 2. Эффективное распараллеливание циклов, вариант «ж»

Обозначения в программах `ref`, `1zh`, `2zh` и `3zh` соответствуют эталонному циклу и задачам 1ж, 2ж, 3ж. Все четыре задачи имеют последовательную реализацию. Эталон запускается также через OpenMP и MPI.

## Зависимости и решение

Расстояние указано от итерации-источника к итерации-приёмнику. Знаки направления получены сравнением индексов источника с индексами приёмника.

| Задача | Зависимость | Распараллеливание |
|---|---|---|
| `ref` | Чтение и запись того же `a[i][j]`, расстояние `(0,0)`, направление `(=,=)`. Между разными итерациями связей нет. | Статическое распределение строк в OpenMP и MPI. |
| `1zh` | Истинная (RAW). `a[i-4][j+2]` записывается раньше его чтения. Расстояние `(4,-2)`, направление `(<,>)`. | MPI распределяет независимые цепочки с шагом `(4,-2)`. Внутри цепочки значения считаются по порядку. Границы разделов выбираются по числу операций, поэтому длинные и короткие цепочки получают разный вес. |
| `2zh` | Антизависимость (WAR). Итерация читает `a[i+2][j-3]` до её возможной перезаписи. От чтения к записи расстояние `(2,-3)`, направление `(<,>)`. | OpenMP читает неизменяемый вход и пишет в отдельную выходную матрицу. Каждый поток заполняет свои строки и копирует только неизменяемые границы. |
| `3zh` | Истинная межцикловая (RAW). Первый цикл пишет `a[i+1][j-2]`, второй использует её в `b[i][j]`. Расстояние `(-1,2)`, направление `(>,<)` по индексам двух циклов. Первый цикл целиком предшествует второму в последовательной версии. | MPI делит сетку по строкам. После вычисления фрагмента `a` следующий ранг передаёт свою первую строку предыдущему через `MPI_Sendrecv`. |

В 1ж начало каждой цепочки лежит в первых четырёх строках или двух правых столбцах. Эти ячейки не меняются в исходном цикле. Все обновляемые ячейки принадлежат ровно одной цепочке, поэтому во время вычисления обмен не нужен. Если требуется выходной файл, ранг 0 собирает цепочки в обычную матрицу. В 3ж левый край `b` и последняя строка остаются нулевыми. Массивы выделяются в куче и поддерживают прямоугольные сетки, включая `5000×5000`.

## Запуск на кластере

Из корня копии репозитория на головном узле:

```sh
cd SEM2/lab_2
make
sbatch run_omp.sh
sbatch run_mpi.sh
squeue --me
```

OpenMP запрашивает один узел и проверяет 1, 2, 4 и 8 потоков. MPI запрашивает два узла по восемь CPU и проверяет 1, 2, 4, 8 и 16 процессов с `mpirun`. Для каждого числа исполнителей скрипты записывают результаты на сетке `77×83` в `results-omp-<id>` или `results-mpi-<id>` и проверяют их через `cmp`. При несовпадении скрипт завершается с ошибкой. Отдельные замеры производительности выполняются на `5000×5000`, по пять повторов, и пишутся как CSV в `loops-omp-<id>.out` и `loops-mpi-<id>.out`.

Размеры и число повторов можно задать перед `sbatch`. Для проверки равенства на полной сетке задайте также `CHECK_ROWS=5000 CHECK_COLS=5000`. Уточните доступное место перед таким прогоном, поскольку каждый текстовый результат может занимать сотни мегабайт. Пример отдельной проверки MPI:

```sh
./loops 1zh seq 77 83 1 seq.txt
mpirun -n 4 ./loops_mpi 1zh 77 83 1 mpi.txt
cmp seq.txt mpi.txt
```

На кластере запускайте MPI внутри выделенных ресурсов Slurm. В OpenMP число потоков задаётся через `OMP_NUM_THREADS`.

## Ускорение и эффективность

Из времени исключены заполнение входов, запись и сбор результата для файла. Копирование границ в 2ж и граничный обмен в 3ж входят в замер. Для каждого MPI-повтора берётся время самого медленного ранга. В CSV записывается медиана повторов. Последовательное время берётся из того же задания Slurm, что и параллельное. Формулы `S = T_seq/T_p` и `E = S/p`.

На машине с Python 3.9+ и Matplotlib 3.6+ из папки `SEM2/lab_2`:

```sh
python3 ../plot_benchmarks.py loops loops-omp-123.out loops-mpi-124.out --out plots
```

Подставьте номера заданий вместо `123` и `124`. Скрипт строит графики для каждого варианта и печатает максимальное измеренное ускорение и соответствующую эффективность. При анализе сравните 1ж с эталонным MPI, чтобы увидеть эффект порядка доступа и разбиения на цепочки. Для 2ж учитывайте дополнительный поток записи в выходную матрицу. Для 3ж сравните 8 и 16 процессов. При размещении на двух узлах часть граничных данных передаётся через сеть.
